# 사주 × 자미두수 계산 엔진 백엔드

## 실행 방법
```bash
pip install -r requirements.txt
uvicorn main:app --host 0.0.0.0 --port 8000
```

## API
`POST /api/chart` — 명식/명반 계산 (API 키 불필요, 완전 무료)

`POST /api/prompt` — **API 키 불필요, 완전 무료.** 명식·명반 데이터가 담긴 AI 해석용 프롬프트 텍스트만 만들어서 반환. 프론트에서 이 텍스트를 사용자가 복사해 claude.ai 등에 직접 붙여넣는 방식으로 사용.
```json
{
  "chart": { "...": "/api/chart 응답 전체를 그대로 넣음" },
  "user_input": {"name":"홍길동","gender":"여성","date":"2002-04-30","time":"16:17","city":"대구","preQuestion":""},
  "detail_level": "summary"
}
```

`POST /api/report` — (선택, API 키 필요) 백엔드가 Anthropic API를 직접 호출해서 완성된 리포트 텍스트를 바로 반환. 과금 발생. 사용자가 많아지면 모든 사용자의 호출 비용이 이 서버(=운영자)에게 청구되므로, 트래픽이 늘기 전까지는 `/api/prompt` 무료 경로 사용을 권장.

## 비용 없이 시작하기 (권장 MVP 경로)
지금 프론트엔드는 기본적으로 `/api/prompt`만 사용해요. 즉:
- 사주/자미두수 계산 → 100% 무료
- AI 해석 → 사용자가 프롬프트를 복사해서 claude.ai 등에 직접 붙여넣어 "각자" 무료로 받음 (운영자에게 비용 청구 안 됨)

나중에 트래픽/반응을 보고 자동화(`/api/report`)로 전환하고 싶다면:
1. console.anthropic.com에서 API 키 발급, 배포 환경변수에 `ANTHROPIC_API_KEY` 등록
2. **반드시** Anthropic 콘솔의 Billing에서 월 지출 한도부터 설정 (사용자가 많아지면 그만큼 비용이 발생하고, 전부 이 키의 소유자에게 청구됨)
3. 프론트엔드를 `/api/prompt` 대신 `/api/report` 호출로 전환, 필요시 사용자별 요청 횟수 제한 로직 추가

## ⚠️ 반드시 알아야 할 아키텍처 제약: py-iztro / pythonmonkey 스레드 이슈

자미두수 계산 라이브러리 `py-iztro`는 내부적으로 **SpiderMonkey JS 엔진을 pythonmonkey로 임베드**해서 돌아갑니다.
이 JS 런타임은 **메인 스레드에서만 안전하게 동작**하고, 별도 워커 스레드에서 호출하면
`InternalError: too much recursion` 오류가 발생합니다 (실제로 개발 중 재현·확인함).

그래서 지켜야 할 규칙:
- `/api/chart` 핸들러는 **반드시 `async def`** 로 정의해야 합니다 (FastAPI가 동기 함수는 자동으로 워커 스레드 풀에서 돌리기 때문에, 그 경우 위 오류가 남).
- **동시성(스케일)은 스레드가 아니라 프로세스 단위로 확보**해야 합니다. 운영 배포 시:
  ```bash
  uvicorn main:app --host 0.0.0.0 --port 8000 --workers 4
  ```
  각 워커 프로세스가 자기만의 JS 런타임을 가지므로 안전합니다. (단일 워커 안에서는 요청이 순차 처리됨 — 자미두수 계산 자체는 수십ms 수준이라 실사용 트래픽에서는 큰 문제 없을 가능성이 높지만, 트래픽이 커지면 워커 수를 늘리거나 아래 대안을 고려하세요.)
- 장기적으로 트래픽이 커지면, 자미두수 계산만 **별도 Node.js 마이크로서비스**(iztro는 원래 JS 라이브러리)로 분리해서 내부 HTTP로 호출하는 구조가 더 안정적입니다. py-iztro는 JS를 파이썬에 억지로 붙인 래퍼라 운영 안정성 측면에서 한계가 있어요.

## 알려진 제약 (다음 단계에서 다룰 것)
- 음력 생년월일 입력 미지원 (양력만) — `Lunar.fromYmd` 경로 추가 필요
- 해외 출생지 미지원 — 도시 경도 테이블에 없으면 기준 경도(127.5E, 보정 0)로 폴백
- `cities.py`는 한국 주요 도시 위주 1차 목록 — 시/군/구 단위 세분화 필요
- 진태양시 보정 기준 127.5°E로 확정 적용됨 (135°E 방식과 다른 결과가 나올 수 있는 유파 차이 있음, 서비스 내 안내 문구 권장)
